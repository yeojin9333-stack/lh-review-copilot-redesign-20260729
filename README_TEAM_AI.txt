LH REVIEW COPILOT
팀원 및 AI 작업 지침
작성일: 2026-07-28

이 파일은 Google Drive에서 프로젝트 압축본을 전달받은 팀원과 AI 도구가 가장 먼저
읽어야 하는 작업 기준서입니다.

======================================================================
1. 프로젝트 목적
======================================================================

LH 공공주택 설계검토에서 다음 과정을 하나의 서비스로 연결하는 프로토타입입니다.

- 사용자의 한 줄 검토 의도 입력
- BIM 대상과 Review Context 6축 자동 확인
- VE 사례와 법령·지침 근거 자동 검색
- 미확인정보와 검토 대안 1·2·3 자동 구성
- AI 판단 사유 초안을 확인하는 전문가 판단
- 설계사 답변 및 수정안 재제출
- LH 최종 반영 확인과 타임라인
- 현재안·대안 1·2·3의 데이터 기반 기대효과 요약

현재 공개 주소:
https://lh-review-copilot-20260727.geonnii.chatgpt.site

중요: 공개 주소는 운영 환경입니다. 명확한 요청과 권한 없이 배포하지 마세요.

======================================================================
2. 현재 기술 구성
======================================================================

- Node.js 22.13 이상
- pnpm
- React / Next.js 호환 구조 / vinext
- react-zoom-pan-pinch 기반 메인 Cutaway와 React Three Fiber 상세 램프 BIM
- Cloudflare Sites
- D1: 전문가 판단, 설계사 답변, LH 반영 상태, 타임라인 저장
- ExcelJS: 표준화 Excel과 시나리오 Excel을 서비스 JSON으로 변환
- 공개 배포: 시나리오 Context와 기대 Evidence를 회수하는 내장 RAG
- 로컬/별도 서버: services/review-copilot-ai-ollama의 Ollama LLM + SQLite 벡터·FTS5 RAG

AI/RAG는 두 실행 모드를 정확히 구분해야 합니다.

- 공개 배포 기본값인 scenario-rag는 실제 근거 회수를 수행하지만 생성형 LLM과
  임베딩 벡터 검색을 사용하지 않습니다.
- REVIEW_COPILOT_API_URL에 FastAPI/Ollama 서버가 연결되면 실제 LLM+벡터 RAG,
  자료 업로드, 근거 기반 후속 질문이 활성화됩니다.
- 외부 백엔드는 Cloudflare Sites와 함께 배포되지 않으며 별도 HTTPS 서버가 필요합니다.
- 외부 LLM 연결 시 대안 초안은 검색 근거와 Provider 응답을 사용하고, 내장 RAG
  또는 Mock 모드에서는 검증 가능한 규칙 템플릿을 사용합니다.
- 메인 Viewer는 시연용 Isometric Cutaway WebP와 동일 Transform 좌표계의
  Hotspot을 사용하고, 상세 Viewer는 Three.js 저복잡도 형상 모델을 사용합니다.
- 대안의 비용·공기·동선 영향은 정성적 검토 가설이며 견적·공정·시뮬레이션
  결과가 아닙니다.
- 기대효과 요약은 ReviewAlternative와 VE 사례의 expected_effects를 재사용하며,
  근거가 없는 비용·공기·안전 점수나 AI 신뢰도를 생성하지 않습니다.
- IFC·PDF 첨부는 실제 파일 업로드가 아닌 Mock입니다.

모든 검토 패키지는 sourceMode: "llm" | "rule" | "mock"을 포함해야 합니다.
개발용 상태 화면에는 Provider 호출 여부와 검색·화면 반영 상태만 표시하고 API 키,
토큰, 비밀정보 값은 절대 표시하거나 기록하지 않습니다.

AI는 내장 RAG를 생성형 LLM 또는 벡터 RAG라고 과장해서 설명하면 안 됩니다.

메인 `ProjectBimViewer`는 단지 전체 위치 맥락과 Pan·Zoom·Hotspot을, 상세
`BimViewer`는 선택 램프와 대안별 형상을 담당합니다. 메인 화면에서 상세 3D
Scene을 함께 렌더링하지 마세요.
상세 램프의 바닥·벽체·진행선·궤적·대안 오버레이는 공통 `RampPathPoint` 경로를
사용합니다. 검토 기본 이동은 상단 탭 클릭이 아니라 하단의 단일 주 버튼을 따릅니다.

3. 압축본을 받은 후 실행
======================================================================

1) Google Drive 동기화 폴더 밖의 새 로컬 폴더에 압축을 풉니다.
2) 터미널에서 프로젝트 폴더로 이동합니다.
3) 다음 명령을 실행합니다.

corepack enable
pnpm install --frozen-lockfile
pnpm dev

수정 완료 후 반드시 다음을 실행합니다.

pnpm lint
pnpm test
pnpm share:check

검증을 통과하지 못하면 새 공유본을 만들거나 배포하지 마세요.

4. Google Drive 협업 규칙
======================================================================

압축 파일은 Git처럼 변경사항을 자동 병합하지 못합니다.

- 각자 같은 기준 ZIP을 별도 로컬 폴더에서 수정합니다.
- 작업 시작 전 팀 채널에 담당자, 작업 범위와 변경 예정 파일을 공유합니다.
- 같은 파일이나 Excel을 여러 명이 동시에 수정하지 않습니다.
- 기존 압축본을 덮어쓰지 않습니다.
- 파일명은 다음 형식을 사용합니다.

  lh-review-copilot_YYYYMMDD_HHMM_작성자.zip

- 변경 후 TEAM_CHANGELOG.md에 변경 내용, 데이터 변경 여부, 검증 결과를 기록합니다.
- Google Drive에는 최신본과 직전 백업본을 함께 보관합니다.
- 여러 명이 동시에 작업했다면 배포 전에 한 명이 수동으로 변경사항을 통합합니다.

다음 폴더와 파일은 공유 ZIP에 포함하지 않습니다.

- node_modules
- dist
- .vinext
- .wrangler
- .next
- .git
- .env, .env.local 등 환경변수 파일
- .openai/hosting.json
- API 키, 인증 토큰, 개인 키

5. AI 도구에 작업을 맡길 때의 필수 규칙
======================================================================

AI는 작업 전에 이 파일과 다음 파일을 읽어야 합니다.

- TEAM_START_HERE.txt
- README.md
- TEAM_GUIDE.md
- TEAM_CHANGELOG.md
- package.json
- .openai/TEAM_DEPLOYMENT_NOTICE.txt

AI에게 다음 원칙을 명시하세요.

1) 기존 구조와 사용자 변경사항을 보존한다.
2) pnpm과 현재 lockfile을 유지한다.
3) .openai/hosting.json을 만들거나 수정하지 않고 새 사이트를 만들지 않는다.
4) 요청받지 않은 기능, 데이터 삭제, 외부 전송, 공개 배포를 하지 않는다.
5) 비밀정보를 코드, 로그, ZIP, Google Drive에 기록하지 않는다.
6) data/ve-context.json, data/ramp-scenarios.json,
   drizzle/0001_seed-cases.sql을 직접 수정하지 않는다.
7) 데이터 변경은 shared-data의 원본 Excel을 수정한 후 data:build 또는
   scenario:build 명령으로 반영한다.
8) 기능 변경 후 lint, build/test 결과를 확인한다.
9) 배포 전 변경 파일, 데이터 영향, 알려진 한계를 보고한다.
10) scenario-rag와 외부 Ollama LLM+벡터 RAG를 명확히 구분해서 설명한다.

AI에게 전달할 기본 프롬프트 예시:

---
이 폴더는 LH Review Copilot 팀 공유본이다.
먼저 README_TEAM_AI.txt, TEAM_GUIDE.md, README.md를 읽고 현재 구조와 제한사항을
확인해라. 기존 변경사항과 pnpm 구조를 보존하고 .openai/hosting.json을 만들지 마라.
요청한 범위만 수정하고, 데이터 생성 파일은 직접 편집하지 마라.
수정 후 pnpm lint, pnpm test, pnpm share:check를 실행하고 변경 파일, 데이터 영향,
검증 결과, 배포 여부를 보고해라. 명확한 승인 없이 운영 사이트를 배포하지 마라.
---

7. RAG·LLM 기능을 수정하거나 외부 서버에 연결하는 경우
======================================================================

현재 구현 구성:

- app/api/ai/[...path]/route.ts: 외부 백엔드 연결 여부에 따라 실행 모드 선택
- lib/review-copilot-server.ts: 공개 배포용 시나리오 내장 RAG
- services/review-copilot-ai-ollama: FastAPI, Ollama, SQLite 벡터 + FTS5
- REVIEW_COPILOT_API_URL 미설정: scenario-rag
- REVIEW_COPILOT_API_URL 설정: 외부 LLM+벡터 RAG 프록시

외부 Ollama 서버를 로컬에서 실행:

cd services/review-copilot-ai-ollama
./scripts/start_prototype_mac.sh --dry-run
./scripts/start_prototype_mac.sh --yes

Windows는 scripts/start_prototype_windows.ps1을 사용합니다.

추가 개선 시 지킬 구성:

1) 법령·지침·VE 원문을 문단 또는 조문 단위로 분할한다.
2) 각 조각에 doc_id, 문서명, 판본, 시행일, 페이지, 조문, case_id를 저장한다.
3) 임베딩을 생성해 벡터 저장소에 저장한다.
4) 키워드 검색과 벡터 검색을 결합한다.
5) 필요하면 재정렬 모델로 상위 근거를 다시 정렬한다.
6) 서버 API에서 검색된 근거만 사용해 LLM 답변을 생성한다.
7) 답변에 문서명, 조문, 페이지, 공식 출처를 표시한다.
8) 근거가 부족하면 추측하지 말고 미확인으로 반환한다.
9) 평가정답 시트의 질의로 Recall@5, MRR, 근거 정확도를 측정한다.
10) 전문가의 채택·수정·기각 피드백을 평가 데이터로 저장한다.

권장 API 예시:

- POST /api/rag/search   : 근거 검색
- POST /api/rag/answer   : 인용이 포함된 답변 생성
- POST /api/rag/feedback : 전문가 평가 저장

보안 규칙:

- LLM API 키는 서버 환경변수에서만 읽습니다.
- 키를 브라우저 코드에 포함하지 않습니다.
- .env.local은 공유하거나 압축하지 않습니다.
- 저장소에는 키 이름만 있는 .env.example을 둘 수 있습니다.
- 운영 키는 배포 서비스의 환경변수로 등록합니다.
- 프로젝트 원문과 사용자 입력을 외부 모델에 전송할 수 있는지 먼저 확인합니다.

RAG 수정 후 필수 검증:

- 근거가 없는 답변을 생성하지 않는지
- 다른 법령 판본을 섞지 않는지
- 페이지와 조문 인용이 실제 원문과 일치하는지
- 사용자 권한에 따라 검색 가능한 문서가 분리되는지
- API 장애 시 기존 검토 화면이 안전하게 동작하는지

8. 배포 방법
======================================================================

가장 안전한 방법은 배포 담당자 한 명을 지정하는 것입니다.

1) 팀원이 수정본 ZIP과 TEAM_HANDOFF 문서를 Google Drive에 업로드합니다.
2) 통합 담당자가 ZIP을 새 폴더에 풀고 기존 최신 원본과 비교합니다.
3) 충돌을 해결해 배포 담당자의 원본 폴더에 변경사항만 병합합니다.
4) pnpm install, pnpm lint, pnpm test, pnpm share:check를 실행합니다.
5) TEAM_CHANGELOG.md와 데이터 영향을 확인합니다.
6) 기존 Sites 프로젝트에 새 버전으로 배포합니다.
7) 공개 주소에서 대표 화면과 API를 확인합니다.

배포 후 확인 항목:

- /
- /review
- /decision
- /designer
- /api/cases
- /api/cases/DET-2022-P098
- /api/workflow
- /api/ai/health
- POST /api/ai/review

팀 공유본에는 .openai/hosting.json이 없습니다. 이 파일은 배포 담당자의 기존 원본
폴더에서만 관리하며, 팀원은 검증된 수정 ZIP을 배포 담당자에게 전달합니다.

Google Drive에 ZIP을 업로드하는 것만으로 사이트가 자동 배포되지는 않습니다.

9. 현재 보안 및 운영 주의사항
======================================================================

- 현재 사이트는 공개 상태입니다.
- 업무 저장 API의 사용자 인증과 역할별 쓰기 권한이 충분하지 않습니다.
- 민감한 실제 프로젝트 자료, 개인정보, 비공개 도면을 넣지 마세요.
- 실제 서비스 적용 전 사용자 인증, LH/전문가/설계사 권한 분리, 감사 로그,
  파일 악성코드 검사와 백업 정책이 필요합니다.
- 외부 LLM/RAG를 운영 연결하기 전 문서별 접근권한과 외부 모델 전송 정책을 먼저 정의해야 합니다.

팀원이나 AI는 작업 완료 시 아래 형식으로 보고합니다.

- 작업 목적:
- 변경한 파일:
- 데이터 변경 여부:
- 새로 추가한 의존성:
- 실행한 검증:
- 검증 결과:

안전하게 관리할 수 있습니다.
