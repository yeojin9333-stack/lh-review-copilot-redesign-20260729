LH REVIEW COPILOT · 팀 공유본 시작 안내
기준일: 2026-07-28

이 압축본은 Google Drive에서 내려받아 각자의 로컬 PC와 AI 개발 도구에서
수정하기 위한 소스 공유본입니다.

중요한 원칙
======================================================================

1. 압축을 Google Drive 동기화 폴더 안에서 직접 편집하지 마세요.
   각자 PC의 새 작업 폴더에 압축을 풀어 작업합니다.

2. 이 공유본에는 기존 공개 사이트의 연결 파일인
   .openai/hosting.json이 의도적으로 들어 있지 않습니다.
   로컬 실행에는 필요하지 않으며, 임의로 만들거나 다른 project_id를 넣지 마세요.

3. 팀원은 수정과 검증까지만 진행합니다.
   공개 사이트 배포는 팀에서 지정한 통합·배포 담당자 한 명만 진행합니다.

4. API 키, 비밀번호, 인증 토큰, 실제 값이 든 .env 또는 .env.local은
   코드나 반환 ZIP에 넣지 않습니다.


처음 실행하기
======================================================================

필요 프로그램:

- Node.js 22.13 이상
- pnpm

프로젝트 폴더의 터미널에서 실행:

  corepack enable
  pnpm install --frozen-lockfile
  pnpm dev

터미널에 표시되는 Local 주소를 브라우저에서 엽니다.

로컬 기본 모드에서는 별도 LLM 서버 없이 내장 시나리오 RAG가 동작합니다.
실제 Ollama LLM+벡터 RAG가 필요한 작업만
services/review-copilot-ai-ollama/README.md를 추가로 확인하세요.


AI 도구로 작업할 때
======================================================================

AI에게 아래 파일을 먼저 읽게 하세요.

1. TEAM_START_HERE.txt
2. README_TEAM_AI.txt
3. TEAM_GUIDE.md
4. README.md
5. TEAM_CHANGELOG.md

AI 작업 요청에 다음 문장을 포함하는 것을 권장합니다.

---
이 폴더는 LH Review Copilot 팀 공유본이다.
TEAM_START_HERE.txt와 README_TEAM_AI.txt를 먼저 읽고 기존 구조를 보존해라.
요청받은 범위만 수정하고, .openai/hosting.json을 만들거나 공개 배포하지 마라.
생성 데이터 JSON과 D1 seed SQL은 직접 편집하지 말고 원본 Excel과 생성 스크립트를
사용해라. 작업 후 pnpm lint, pnpm test, pnpm share:check를 실행하고
TEAM_HANDOFF_TEMPLATE.md 형식으로 변경사항과 검증 결과를 정리해라.
---


현재 핵심 사용자 흐름
======================================================================

일반 사용자:

  단지 전체 Cutaway 확인
  → 지하주차장 B1과 곡선형 램프 R-02 Hotspot 선택
  → 검토 의도 한 줄 입력과 AI 준비 애니메이션
  → 상세 램프 BIM과 Context로 Drill-down
  → AI가 준비한 Context 확인
  → 하단 버튼으로 관련 사례 → 법령·지침 → 대안 비교 순차 확인
  → 이대로 전문가 검토 요청

전문가:

  AI가 준비한 패키지와 판단 사유 초안 확인
  → 채택 / 보완 필요 / 기각 선택
  → 필요하면 사유 수정
  → 판단 확정

LH 담당자:

  현재안·대안 1·2·3 기대효과 요약 확인
  → 설계사 답변 대조
  → 최종 반영 상태 저장
  → 조직지식 이력 확인

디자인 시스템, Cutaway·상세 3D BIM, 시나리오 데이터, D1 업무 흐름을 요청 없이 크게
변경하지 마세요.

메인 Cutaway Viewer와 상세 램프 BIM은 서로 다른 컴포넌트입니다. 상세 램프의 바닥,
벽체, 차량 진행선과 대안 오버레이는 하나의 공통 RampPathPoint 좌표를 공유하므로
개별 요소에 임의 좌표를 추가하지 마세요.

AI/RAG 결과에는 sourceMode(llm/rule/mock)가 포함됩니다. 실제 Provider 호출을
추가하거나 수정할 때도 API 키·토큰·비밀정보를 UI, 로그, ZIP에 넣지 마세요.

팀 수정사항의 배포
======================================================================

팀원 ZIP이 Google Drive에 올라오는 것만으로 공개 사이트가 갱신되지는 않습니다.

통합·배포 담당자는 다음 순서로 처리합니다.

1. 수정본을 별도 폴더에 풀고 HANDOFF 문서를 확인
2. 기존 최신 원본과 변경 파일 비교
3. 충돌을 해결해 통합 원본에 반영
4. lint, test, share:check 실행
5. 대표 화면과 AI/RAG API 확인
6. 기존 Sites 프로젝트에 새 버전으로 배포

이 방식이면 팀원은 어떤 AI 개발 도구를 사용해도 되고, 공개 서비스는 검증된
통합본만 반영할 수 있습니다.
